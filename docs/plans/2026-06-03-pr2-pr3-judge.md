# PR 2 + PR 3: LLM-as-Judge Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Wire the LLM-as-judge passes (cited verdicts + uncited claims) end-to-end through `render.py`, `skill/scripts/render.py`, SKILL.md, AGENTS.md, with a real-API empirical smoke gating the v0.3.0 release.

**Architecture:** Skill-side deposit protocol from the design doc (`docs/plans/2026-06-03-llm-judge-and-redesign-design.md`):

```
agent writes answer.md
  ↓
agent renders ONCE (no judge) → produces manifest.json with cite_ids
  ↓
agent reads manifest.json + sources, dispatches fresh subagent per cite
  ↓ writes /tmp/groundling-judge/{verdicts.json, uncited.json}
  ↓
agent renders AGAIN with --judge-dir → produces decorated answer.html
```

**Default-on, opt-out via user request.** SKILL.md / AGENTS.md instruct the model to run the judge by default; user signals like "skip the judge" / "quick answer" / "don't verify" suppress it.

**Tech stack:** No new deps. The judge is purely a deposit-and-decorate flow; render reads JSON, no API calls from render itself.

### Task 2.1: `--judge-dir` flag + verdicts loader + state decoration

**Files:**
- Modify: `src/groundling/render_cmd.py` — add `judge_dir: Path | None = None` kwarg; load `verdicts.json`; stamp `data-state` + `data-judge-note` per cite; flip `has_judge_data` when verdicts present.
- Modify: `src/groundling/answer_html.py` — `build_cite_attrs` accepts an optional verdict dict; `build_answer_html` accepts `has_judge_data: bool` and threads through.
- Modify: `src/groundling/answer_html_inline.py` — `build_inline_answer_html` accepts `verdicts: dict | None`; stamps `state` and `judgeNote` into the `cites_by_id` entries; passes `has_judge_data` to the template.
- Modify: `src/groundling/cli.py` — add `--judge-dir` option on `groundling render`.
- Modify: `skill/scripts/render.py` — add `--judge-dir` flag; load verdicts; pass to `build_inline_answer_html`.

**Behavior:**
- `verdicts.json` shape: `{"1": {"state": "supported|partial|unsupported", "note": "..."}, ...}`. Keys are stringified cite_ids matching manifest.
- Missing entries → cite stays at `data-state="none"`; counter `verdicts_missing` increments on stderr.
- Unknown cite_ids in JSON → ignored; counter `verdicts_unmapped` increments.
- Invalid state value → drop entry + warn.
- Malformed JSON file → skip with warning, continue rendering.
- `--judge-dir` absent or empty → render works as today (no state decoration).
- New stderr counters: `verdicts_missing`, `verdicts_unmapped`.

**Tests:** `tests/test_judge_verdicts.py` (~80 LOC):
- Full coverage of verdicts: every anchor gets `data-state` + `data-judge-note`.
- Partial coverage: present cites decorated, missing ones default-state, counter reports.
- Unknown cite_id: ignored with `verdicts_unmapped`.
- Invalid state value: drop + warn.
- Malformed JSON: skip + warn.
- `has_judge_data=True` is passed only when verdicts.json has at least one valid entry.

Inline-HTML test extension: each verdict state renders the correct CSS class on `a.cite`; hover-card / modal JS branches on `judgeNote`.

## Phase 2: PR 3 — Uncited significant claims (needs-citation)

### Task 3.1: `uncited.json` loader + span-finding + wrap injection

**Files:**
- Modify: `src/groundling/render_cmd.py` — load `uncited.json` from judge_dir; for each entry, find `span_text` in the rewritten answer.md (substring + before_context/after_context disambiguation); wrap matched span with `<a class="cite" data-state="needs-citation" data-uncited-note="...">span_text</a>` (raw HTML survives markdown rendering).
- Modify: `src/groundling/answer_html.py` and `answer_html_inline.py` — needs-citation anchors get the same hover/modal affordance as cited anchors; populate `cites_by_id` (inline path) and the JSON map keys with synthetic IDs (e.g., `u1`, `u2`) so the modal works.

**uncited.json shape (from design):**
```json
[
  {"span_text": "...", "before_context": "...", "after_context": "...", "note": "..."}
]
```

**Span-finding algorithm:**
1. For each entry, find all occurrences of `span_text` in the (rewritten) answer.md.
2. Identify the spans occupied by existing cite link constructions (regex on `[text](cite://N)` and reference-style `[N]` patterns) — these are "claimed" ranges.
3. Filter occurrences: skip any whose `[start, end)` intersects a claimed range → counter `uncited_overlap`.
4. Of remaining: one match → wrap. Multiple → use `before_context`/`after_context` to pick. Still ambiguous or zero → counter `uncited_unmatched`.

**Wrap output (inline-pathway-friendly raw HTML):**
```html
<a class="cite" role="button" tabindex="0" data-cite-id="u1" data-kind="uncited" data-state="needs-citation">span_text</a>
```

`data-cite-id="u1"` (the `u` prefix distinguishes from numeric cite_ids; modal lookup keys on it).

For both `answer_html.py` and `answer_html_inline.py`: extend the cites JSON / cite_records to include synthetic uncited entries with `kind: "uncited"`, `state: "needs-citation"`, `judgeNote: "..."`, `claim: span_text`. Hover card and modal handle the new kind: no source crop / no excerpt; show judge note in place of source.

**Tests:** `tests/test_judge_uncited.py` (~80 LOC):
- Single match → wraps correctly.
- Multiple matches + disambiguator → picks right one.
- Multiple matches + no disambiguator → drops, counter +1.
- No match → drops, counter +1.
- Span overlaps existing `[text](cite://N)` → drops with `uncited_overlap`.
- Malformed entry (missing span_text) → skip + warn.
- Resulting HTML has `<a class="cite" data-state="needs-citation" data-kind="uncited">span</a>` exactly.

Inline-HTML test extension: needs-citation anchor renders dashed-blue underline; modal shows "Needs citation" band + judge note; no source crop slot.

```
Output a JSON array. Empty array if no uncited claims.
```

## Out of scope

- A standalone `groundling judge` CLI subcommand (skill-side deposit pattern; design doc explicitly excludes a CLI judge).
- Caching verdicts across runs.
- Cross-cite reasoning (the per-cite subagent sees only one cite at a time).
- API-side judge (would reintroduce `anthropic` as a runtime dep).
