# groundling: design

**Date:** 2026-05-30
**Goal:** A low-friction Claude-Code-native tool for grounded Q&A over a
folder of PDFs, with citations the user can click to verify against the
original source.

The shape: one CLI, three deps, no backend. The user installs the tool
with `pipx install groundling`, drops an `AGENTS.md` into their project,
and asks Claude Code questions. The tool prints markdown to stdout with
citation links; clicking a link opens a static HTML page that shows the
cited PDF page with the cited words highlighted.

This design is the standalone-product distillation of the heavier
`groundswell_ask` work in `~/.../groundswell/.worktrees/grounded-qa/`.
That worktree validated the end-to-end architecture (Anthropic citations
API + offset_map → bbox highlights, including hybrid web search via
Anthropic's `web_search_20250305` tool); this is the trimmed,
adoption-focused version intended for distribution.

## Context

Two design goals push the architecture:

1. **Adoption-first.** Install in one command. Set one env var. Drop one
   file. No infrastructure decisions, no database, no Azure account, no
   web server, no FastAPI, no project model. The user's only mental
   commitment is "PDFs in a folder, ask a question, get a markdown
   answer with verifiable citation links."

2. **Claude-Code-native.** The answer surface is Claude Code itself —
   the user reads the markdown answer in the agent's chat. Only when
   they want to verify a citation do they click a link and open the
   static HTML viewer. We do not build an answer UI of our own; Claude
   Code is it.

These two goals together force a particular set of decisions: no
backend (static files only), minimal deps (PyMuPDF replaces both Azure
DI and PDF.js), opinionated CLI (one subcommand, one core flag), and
opinionated output (markdown to stdout, static HTML on disk).

## Key decisions (validated during brainstorm 2026-05-30)

1. **Name: `groundling`.** Ties to the `groundswell` lineage (a
   groundling is the lighter, ground-floor relative). Distinctive,
   unclaimed, works as both CLI command and PyPI package name.
2. **Scope: doc Q&A + opt-in web search.** v1 includes the
   `--web-search` flag and both citation types. Web-only mode and
   shareable `answer.html` are deferred.
3. **PDF extraction: PyMuPDF only.** Hard-fail with a clear message on
   PDFs with no extractable text (scans). No OCR, no Docling fallback
   in v1. Most curated data rooms are text-native and PyMuPDF handles
   them well enough.
4. **Input: PDFs only.** No HTML, no URL flags, no Markdown. The corpus
   is a flat directory of `.pdf` files.
5. **Citation viewer: page image + sidebar + cite navigation.** Each
   `cites/N.html` shows the cited PDF page rendered as PNG with
   yellow-rectangle bbox overlays, a left sidebar with the question
   and `cited_text`, and prev/next links between cites in the same run.
   No JavaScript; pure HTML+CSS.
6. **CLI shape: `groundling ask "..."`.** Explicit subcommand leaves
   room for `groundling list` etc. without breaking compatibility.
7. **Output: markdown to stdout.** Claude Code consumes it as a tool
   result. No `answer.html` generated by default.
8. **Citation link uniformity: every `[N]` in the markdown points at
   `file://abs/path/cites/N.html`.** Web cites are wrapped in a 5-line
   meta-redirect stub that bounces to the Chrome Text Fragments URL.
   Uniform link shape upstream, dispatch to the right destination
   downstream.

## Architecture

```
┌────────────────────────────────────────────────────────────────┐
│ Claude Code session                                             │
│   user: "what was BYD's Q1 revenue?"                            │
│   agent reads AGENTS.md, runs:                                  │
│     groundling ask --corpus docs/ "..."                         │
│            ↓                                                    │
│   prints markdown to stdout:                                    │
│     BYD's Q1 revenue was X.[1]                                 │
│     [1]: file:///abs/path/qa-runs/.../cites/1.html             │
│            ↓                                                    │
│   user clicks [1] in terminal → browser opens                   │
└────────────────────────────────────────────────────────────────┘
                       │
                       ↓
┌────────────────────────────────────────────────────────────────┐
│ `groundling ask` (one Python CLI, single venv)                  │
│   1. walk corpus/*.pdf                                          │
│   2. for each PDF: PyMuPDF → words[] with bboxes                │
│      (error clearly if a PDF has no text — scan)                │
│   3. linearize words into text + offset_map keyed by            │
│      char_start/char_end → (page, bbox, word_idx)               │
│   4. call Anthropic Messages API:                               │
│        - documents=[linearized text per PDF, cache_control]     │
│        - citations enabled                                      │
│        - optionally: web_search_20250305 tool                    │
│   5. walk response.content blocks; resolve each citation:       │
│        - char_location → offset_map → (page, bboxes)            │
│        - web_search_result_location → (url, cited_text)         │
│   6. write run dir:                                             │
│        cites/N.png (rendered page via PyMuPDF)                  │
│        cites/N.html (image + sidebar + prev/next nav)           │
│        manifest.json (debug + future replay)                    │
│   7. emit markdown to stdout with citation links                │
│        - PDF cites → file:///abs/path/cites/N.html              │
│        - web cites → cites/N.html (redirect stub to             │
│           <url>#:~:text=<encoded_cited_text>)                   │
└────────────────────────────────────────────────────────────────┘
```

**Three Python deps**: `anthropic`, `pymupdf`, `jinja2`.

**Project layout**:

## PDF extraction and linearization

Per PDF, PyMuPDF's `page.get_text("words")` returns one tuple per word:
`(x0, y0, x1, y1, content, block_no, line_no, word_no)`. We accept
PyMuPDF's reading order without correction. Words are concatenated with
single spaces into a flat linearized text; each word's char range in
that text is recorded in an `offset_map` entry with its `(page, bbox)`.

```python
parts: list[str] = []
entries: list[dict] = []
cursor = 0
for i, w in enumerate(words):
    if i > 0:
        parts.append(" ")
        cursor += 1
    parts.append(w["content"])
    entries.append({
        "char_start": cursor,
        "char_end":   cursor + len(w["content"]),
        "page":       w["page"],
        "bbox":       w["bbox"],
    })
    cursor += len(w["content"])
linearized = "".join(parts)
```

**No paragraph segmentation, no table inference.** Every word is its
own offset_map entry. Citation char ranges from Anthropic resolve to a
list of overlapping word entries via `resolve_range` (bisect lookup;
same algorithm as the worktree version).

**Per-PDF cache** under `<corpus>/.groundling-cache/<pdf-stem>.json`,
keyed by PDF mtime. Skip re-extraction on cache hits.

**Hard-fail on scans.** When `get_text("words")` returns empty for a
PDF, raise `NoTextError` with a clear message:

```
BYD-Q1.pdf: no extractable text. This looks like a scanned PDF;
groundling v1 doesn't OCR. Either OCR it externally first, or use a
text-native version.
```

CLI maps `NoTextError` to exit code 3.

## Anthropic Messages API and citation walking

One `messages.create` per question. Request shape (identical to the
worktree version minus the Azure-DI sidecar context strings):

```python
client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=4096,
    system=SYSTEM_PROMPT,
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "document",
                "source": {"type": "text", "media_type": "text/plain",
                           "data": linearized_text},
                "title": pdf_filename,
                "citations": {"enabled": True},
                "cache_control": {"type": "ephemeral"},
            }
            for pdf_filename, linearized_text in docs
        ] + [{"type": "text", "text": question}],
    }],
    tools=[{
        "type": "web_search_20250305",
        "name": "web_search",
        "max_uses": 5,
    }] if web_search else [],
)
```

**System prompt** keeps the block-splitting nudge from the worktree
experiments — "emit each distinct factual claim as its own text
block." Empirically: tighter source ranges for focused queries,
distinct cites for multi-section answers.

**Citation walker** branches on `cit.type`:

- `char_location` → load the doc's offset_map, call `resolve_range`,
  produce a manifest entry with `source_type: "pdf"`, `doc_idx`,
  `char_start/end`, `cited_text`, `spans: [{page, bbox}, ...]`.
- `web_search_result_location` → produce a manifest entry with
  `source_type: "web"`, `url`, `title`, `cited_text`, `encrypted_index`.
- Other citation types (page_location, content_block_location) aren't
  produced by this app's input shape and are skipped silently.

**Markdown emission** concatenates `response.content` text blocks in
order; appends `[N]` markers at the end of each cited block. A small
whitespace-safety check inserts a space between adjacent blocks when
neither has separating whitespace. References at the bottom point at
`file:///abs/path/cites/N.html` regardless of `source_type`.

## Run directory layout

Each invocation creates one run dir under `<corpus>/qa-runs/`. Each run
dir is fully self-contained (deleting it cleans up; tar-ing it makes
the cite viewers shareable).

```
<corpus>/qa-runs/
  └── 2026-05-30T14-32_byd-q1-revenue/
      ├── question.txt
      ├── manifest.json
      ├── response.json
      └── cites/
          ├── 1.html      ← PDF cite viewer
          ├── 1.png       ← rendered PDF page (deduped across cites)
          ├── 2.html
          ├── 2.png
          ├── 3.html      ← web cite redirect stub
          └── ...
```

**Run dir name** = `<utc-timestamp>_<question-slug>`. Slug is the first
5–6 lowercased non-stopword tokens from the question joined with `-`,
capped at ~50 chars. Falls back to a 6-char hex if the slug is empty.

**`manifest.json` shape:**

```json
{
  "run_id": "2026-05-30T14-32_byd-q1-revenue",
  "question": "what was BYD's Q1 2025 revenue?",
  "model": "claude-sonnet-4-6",
  "web_search": false,
  "docs": [{"doc_idx": 0, "pdf_path": "/abs/path/BYD-Q1.pdf"}],
  "citations": [
    {"cite_id": 1, "source_type": "pdf", "doc_idx": 0,
     "char_start": 12834, "char_end": 12892,
     "cited_text": "Operating revenue (RMB) 170,360,448,000.00",
     "spans": [{"page": 24, "bbox": [120.3, 480.1, 215.7, 495.4]}, ...]},
    {"cite_id": 2, "source_type": "web",
     "url": "https://example.com/article",
     "title": "BYD Q1 review",
     "cited_text": "Analysts expected RMB 179.66 billion",
     "encrypted_index": "EncIdx…"}
  ]
}
```

**No GC.** Document in the README: gitignore `qa-runs/`, delete
manually when you want. Run dirs are independent.

## Static HTML generation

Two Jinja2 templates. No JavaScript.

**`cite_pdf.html.j2`** — page image + sidebar + nav.

```
┌─────────────────────────┬──────────────────────────────────┐
│ Citation 2 / 9          │                                  │
│                         │  ┌────────────────────────────┐  │
│ Question                │  │                            │  │
│ what was BYD's Q1 …     │  │   [rendered PDF page]      │  │
│                         │  │                            │  │
│ Cited text              │  │   ████ ← highlight overlay │  │
│ "Operating revenue      │  │                            │  │
│  (RMB) 170,360,448,000" │  │                            │  │
│                         │  │                            │  │
│ Source                  │  └────────────────────────────┘  │
│ BYD-Q1.pdf, page 24     │                                  │
│                         │                                  │
│ ← prev    next →        │                                  │
└─────────────────────────┴──────────────────────────────────┘
```

PDF page rasterised once at 2× scale via
`page.get_pixmap(matrix=fitz.Matrix(2.0, 2.0))`; bbox coords (in PDF
user-space points) multiplied by 2 to land on image pixels. Highlight
divs are absolute-positioned over the image with a 35%-opacity yellow
fill.

**Page dedup**: when multiple citations land on the same PDF page, the
PNG is rendered once and reused across cite HTMLs. Each cite HTML
still owns its own bbox overlay set.

**`cite_web.html.j2`** — 5-line meta-redirect stub.

```html
<meta http-equiv="refresh" content="0;url={{ fragment_url }}">
<title>→ {{ title }}</title>
<p>Redirecting to <a href="{{ fragment_url }}">{{ title }}</a>…</p>
```

`fragment_url` is built as `<url>#:~:text=<urlencoded(cited_text)>`
with a trailing ellipsis stripped (Anthropic truncates `cited_text` to
150 chars with `…`; the ellipsis isn't in the source page, so leaving
it in would prevent the fragment match).

## CLI surface and `--web-search` flag

```
groundling ask "question"
    --corpus DIR
    [--model MODEL]               default: claude-sonnet-4-6
    [--web-search]                opt-in
    [--state-dir DIR]             default: <corpus>/qa-runs
    [--cache-dir DIR]             default: <corpus>/.groundling-cache
```

**Stdout** is `answer.md` verbatim — reference-style markdown with
citation links.

**Stderr** carries token counts + estimated cost after each call so
the user can see what the call cost.

**Exit codes**:

| Code | Meaning |
|------|---------|
| 0 | Success |
| 2 | Corpus has zero PDFs |
| 3 | PDF text-extraction failed (scan / encrypted) |
| 4 | Anthropic API call failed |
| 5 | Zero citations returned (ungrounded answer) |

`.env` autoload via `python-dotenv` so `ANTHROPIC_API_KEY` works
without a global export.

## Distribution and install story

**Single command:**

```
pipx install groundling
# or:  uv tool install groundling
# or:  uvx groundling ask ...    (no install, run once)
```

`pyproject.toml` uses Hatchling; `[project.scripts] groundling =
"groundling.cli:app"`. Python 3.11+.

**AGENTS.md** is shipped both as a template file in the repo
(`AGENTS.md` at the project root, intended for users to copy) and
reproduced inline in the README so it's copy-pasteable without
cloning.

```markdown
# Grounded Q&A — groundling

When a user asks a research question and there's a `docs/` folder of
PDFs, answer it by running:

    groundling ask --corpus docs/ "<question>"

The command prints markdown to stdout. Each cited claim is a clickable
link. Pass the markdown through to the user verbatim — they will click
links to verify sources.

If the user wants the answer to also draw on current web sources, add
`--web-search`. Default is docs-only.

Exit codes: 0 success, 2 no PDFs, 3 scan/encrypted PDF, 4 API failure,
5 zero citations.

State under `<corpus>/qa-runs/` (gitignore it). Cache under
`<corpus>/.groundling-cache/`.

Requires `ANTHROPIC_API_KEY` in env or `.env`.
```

## Out of scope (deferred to v1.1+)

- Scanned PDFs / OCR fallback.
- Web-only mode (`groundling research "..."` without `--corpus`).
- Domain allowlists / blocklists for web search.
- `groundling list` for browsing past runs.
- `groundling replay <run-id>` (manifest is sufficient; build when
  needed).
- Shareable `answer.html` for off-Claude-Code sharing.
- Web archive / Wayback snapshots of cited pages.
- "Sources consulted but not cited" affordance.
- Paragraph segmentation, table inference, header/footer filtering.
- Non-Anthropic LLM backends.
- HTML / Markdown / DOCX inputs.

## Risks

- **PyMuPDF reading order on complex layouts.** Two-column academic
  papers and intricate magazine layouts can produce a garbled
  linearization. The model often still answers correctly because it
  pattern-matches around the noise; cited bboxes are still correct
  (per-word). But the answer quality drops. Documented limit, not a
  v1 blocker.
- **Scans cause exit-3 failures.** Users with mixed corpora will hit
  this; the error message has to be clear enough that they understand
  the cause and the workaround (OCR externally, then re-import). The
  CLI surfaces it explicitly.
- **`file://` URL clickability is terminal-dependent.** Modern
  terminals (iTerm2, Kitty, GNOME Terminal, VS Code) handle OSC 8
  hyperlinks; older ones may not. Claude Code's own UI handles them.
  For TUI clients that don't, the user can still copy-paste the
  path. Document the assumption.
- **Web rot.** Text Fragments fail silently when the source page is
  edited. The user is told they're getting a live web link, not a
  pinned snapshot. v1.5 could add Wayback snapshots.
- **Cost transparency.** Anthropic charges per token + per web search
  ($0.01/search). Surface token + cost estimates on stderr after each
  call so users aren't surprised.

## Done criteria

- `pipx install groundling` succeeds on a fresh machine.
- `groundling ask --corpus DIR "question"` prints markdown to stdout
  with reference-style citation links.
- Clicking a `[N]` link in a modern terminal opens a static HTML page
  showing the cited PDF page with the cited words highlighted.
- `--web-search` adds web citations as Text Fragments URLs that
  highlight the cited sentence in the destination page when opened in
  any modern browser.
- `tar czf run.tar.gz qa-runs/<run-id>` produces a portable artefact
  the recipient can untar and browse offline.
- `pytest tests/` is green.
